本次没有放宽 300 ms 报价年龄、200 ms 跨市场时间差和 4.20 入场阈值。

## 停止控制与覆盖边界

实际停止挂单后，网页行情会话保持 RUNNING，挂单任务为 paused，全库无未完成订单。
此次停止瞬间没有活动挂单，因此现场检查证明的是停止循环等待并保持清空状态；
“持有挂单时停止并等待撤单确认”由自动回归测试覆盖，没有把它描述成此次现场观测。

真实行情在这段窗口只触发 A；B 方向的价格复核、方向选择及挂撤单由自动测试覆盖，未宣称取得 B 的现场订单样本。
确认次数和迟滞时长按保存的摘要核对，未保存每条 Tick 的完整轨迹，不能进行独立逐 Tick 回放。
Paper 没有模拟成交，所以该结果不证明 Maker 成交概率、部分成交处理、MT5 对冲或净收益。

自动测试共 **78 项通过**，包括错误价格、未来时间、确认不足、错误撤单原因、重复生命周期及重叠挂单的检测。
详细 JSON 与停止检查记录保留在 Git 忽略的 data 目录，代码仓库只提交汇总结论。

## 重复执行

```powershell
.\.venv\Scripts\python.exe -m arbitrage.audit --database data/mt5-paper.db --output data/paper-audit.json
```

审计工具通过只读事务固定数据库快照，不创建缺失的数据库，也不修改策略或订单。
它检查最新会话：`fail` 表示检测到记录不一致，命令退出码为 1；`limited` 表示证据缺失、没有订单或仍有未完成订单；
`pass` 表示本次记录检查通过。运行中的循环可能产生新订单，所以报告始终以保存的截止快照为准。
