# 本地监控面板

本次增量为 Phase 1 添加中文网页，继续使用同一个 asyncio Paper 引擎。
网页不包含修改交易模式或真实下单的入口。

## 生命周期

`STOPPED → STARTING → RUNNING → STOPPING → STOPPED`。
初始化、行情、数据库或执行器发生异常时，会话结束并显示 `ERROR`，错误可在页面查看。
手动再次启动会重新初始化并执行数据库状态核对。已有未完成记录时引擎仍进入 `SAFE_MODE`。

开始连接时的停止请求会被记住；底层受限时的 MT5 初始化/网络调用返回后完成清理，
按钮保持“正在停止”，不会并发启动新一轮。停止请求通过原有 stop event 传递到行情任务，
退出时执行模拟撤单并保存状态，不用终止子进程的方式清理策略。

网页服务和行情会话各有生命周期。关闭浏览器不停止 Python 服务或行情会话。
页面停止按钮只停止行情和 Paper 策略，网页及只读历史接口继续服务。

## 接口

| 路径 | 用途 |
| --- | --- |
| `GET /` | 中文面板 |
| `GET /api/status` | 当前引擎状态、Quote、确认、metrics、最近事件、控制 token |
| `GET /api/history` | 只读 SQLite 最近 50 笔模拟订单，不创建不存在的数据库 |
| `POST /api/start` | 启动一轮 Paper，会话活动时重复请求不产生第二轮 |
| `POST /api/stop` | 请求正常停止与模拟订单清理 |

服务固定监听回环地址；POST 必须带同源 Origin（浏览器请求）及 `X-Control-Token`。
不允许跨站控制，不向外部域名提供 CORS。静态资源随 Python 包安装，浏览器不从 CDN 加载脚本。
控制 token 每次服务启动重新生成，API 响应不缓存；这些限制用于本机监控，不构成公网认证系统。

## 数据展示

### 选择挂单方向

“允许挂单的方向”支持仅 A（空 Binance / 多 MT5）、仅 B（多 Binance / 空 MT5）、双向自动。
两个方向的价差始终展示；只有启用的方向可以累计确认和创建 Paper 挂单。
双向自动沿用单挂单槽，有多个候选时选择 Edge 较大者。

运行中切换由行情消费任务串行应用，页面区分请求设置与实际生效设置。切换时复位连续确认；
已有挂单若被新设置禁用，先请求撤单并等待确认，然后才能创建新方向挂单。已有允许方向挂单继续按原撤单规则管理。
选择方向不会绕过价差阈值、行情时间检查或安全模式，也不会直接模拟成交。

网页选择保留在本次网页服务内，刷新页面或停止/启动 Paper 后保留；重启 Python 服务会读取配置中的
`entry.direction_mode: a | b | both`（默认 `both`）。不会自动改写本机 YAML。
`POST /api/direction` 接受 `{"mode":"a"}`、`{"mode":"b"}` 或 `{"mode":"both"}`，使用同样的本地控制保护。

行情和方向数值仍以 Decimal 字符串从 Python 输出；浏览器将图表坐标转换为 Number
只用于绘制，不参与任何交易计算。界面按当前时间重新检查 age/skew，但使用独立只读检查器，
不改变策略确认、计数器或订单。历史订单读连接以只读模式打开，不修改执行器事务。

双向入场价差只要两边已有报价就显示：A 为 `Binance Ask − MT5 Ask`，B 为 `MT5 Bid − Binance Bid`，
遵循 Binance Maker 挂单价格的计算方式。`Edge = 入场价差 − 入场阈值`，不是成交收益。
过期、时间差超限、时间超前或会话停止时，保留最后报价计算的数值，标明“价差仅供观察”及原因，
不使其成为入场信号；缺少任一边报价仍显示空值。图表继续只绘制通过时间校验的价差。

最近事件缓冲最多 200 条，响应取最后 50 条；逐 Tick 快照不加入此缓冲。
网页模式不将每个行情快照重复输出到控制台，关键事件和数据库采样仍保留。
订单列表限定滚动高度，避免 50 条历史把实时面板挤出屏幕。
