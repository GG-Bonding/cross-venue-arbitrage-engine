# 本地监控与手动条件挂单

## 当前行为

实时行情入口使用 ManualOrderStrategy。启动监控不会自动产生订单，只有用户手动创建的条件单可以进入执行。
旧版全局方向及挂单接口返回 HTTP 410，旧页面也不能继续通过这些接口启动全局循环。
离线 --demo 保留合成行情演示，它不是实时行情入口。

顶部同时展示双边 Bid/Ask 和两个方向的实时入场价差：

- A：空 Binance / 多 MT5，Binance Ask − MT5 Ask。
- B：多 Binance / 空 MT5，MT5 Bid − Binance Bid。

这是当前报价的入场价差，不是已挂订单的价差。缺少任一边报价时显示空值；时间检查不通过时保留观察值并标注原因。
图表只绘制通过时间校验的报价。界面采样不增加入场确认次数，也不修改策略订单。

## 每笔条件单

每笔独立提交方向、入场价差、撤单价差、数量和循环选项。价格与数量通过 Decimal 处理，
数量必须满足当前合约步长和最小/最大数量。入场价差允许负数，比较规则仍为“实时价差 ≥ 本单阈值”，
撤单价差不能高于入场价差。每笔单有自己的确认状态，共同使用配置的最少 Tick 数和持续时间；
报价过期、超前或时间差超限会重置确认。

只有 WAITING 状态的合格单参与调度。多笔合格单按 queue_seq 选一笔；不合格队首不阻塞其他合格单。
调度器在写入数据库前先保留唯一执行槽，不会在等待数据库时让第二笔占用。
执行中或撤单确认中，其他条件单不执行，也不沿用占槽期间的旧确认。

每次触发创建一笔 Paper Maker 单，记录 conditional_id。成交数量仍为 0，本阶段没有模拟撮合、部分成交或对冲。
该单撤销后，单次条件单为 DONE（页面显示“本次结束 · 模拟单已撤”）；循环单回到 WAITING 并排至队尾，
避免循环单一直抢占执行槽。取消活动条件单先撤 Maker 单，确认撤单后才释放槽。

## 持久化与恢复

SQLite conditional_orders 表保存请求参数、队列顺序、状态、执行次数和关联执行订单。
状态转换与 strategy_events 审计事件同事务写入。HTTP 操作进入有界命令队列，由行情消费任务串行提交数据库，
提交成功后才返回成功响应。请求 ID 为 UUID；重复提交相同请求不会创建第二笔，同 ID 不同参数会拒绝。
最多 100 笔未结束条件单；页面保留这些单子及最近结束的 50 笔，完整历史保留在 SQLite。

停止监控时取消当前模拟执行，待执行条件单进入 PAUSED。重启监控只加载队列，不自动恢复，用户可逐笔恢复。
进程异常退出时 EXECUTING/CANCELING 条件单进入 REVIEW，不能自动再次执行。
保留执行槽后未能确认生成执行单的异常也进入 REVIEW，不误标为完成。
旧 Maker 记录未清理时沿用 SAFE_MODE，不绕过状态核对。

## 接口

| 接口 | 用途 |
| --- | --- |
| GET /api/status | 行情、条件队列、唯一活动条件单、执行单和公共配置 |
| GET /api/history | 最近 50 笔执行订单，保留旧版本记录 |
| POST /api/start、/api/stop | 启动/停止行情会话与清理 |
| POST /api/conditions | 创建手动条件单 |
| POST /api/conditions/{UUID}/cancel | 取消指定条件单 |
| POST /api/conditions/{UUID}/resume | 恢复指定 PAUSED 条件单 |
| POST /api/direction、/api/placement | 已停用，返回 410 |

创建请求示例：

```json
{
  "request_id": "ccb30e15-0127-4a9c-b055-d99c0c0ca419",
  "direction": "SHORT_BINANCE",
  "entry_threshold": "4.20",
  "cancel_threshold": "4.00",
  "quantity": "1",
  "repeat": false
}
```

服务只监听 127.0.0.1；POST 验证同源 Origin 和 X-Control-Token，禁止跨站控制，不开放 CORS。
静态资源随 Python 包安装，不依赖外部 CDN；响应不含账户凭据、代理或终端路径。
同库使用 OS 会话锁，网页和另一个实时行情进程不能同时运行该策略。

## 验证范围

测试覆盖无手动单不执行、A/B 各自阈值、多单同时满足时互斥、跳过不合格队首、循环公平性、
取消排队及活动单、幂等提交、无效行情、重启暂停、异常执行防重入和审计关联。
